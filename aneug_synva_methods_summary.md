# Methodology Summary: AneuG and SynVA

This file summarizes the methods of two intracranial-aneurysm (IA) mesh-generation
works. **AneuG** is the "energy work" (the GHD + Morphing-Energy-Alignment paper) that
the coding agent already knows well, so it is covered briefly. **SynVA** is the newer
toolkit built on top of it, covered in more detail.

---

## 1. AneuG (the energy work) — brief

Two-stage conditional VAE that jointly models the **aneurysm complex** and its **parent
vessels**.

- **Shape encoding (stage 1):** The aneurysm complex (IA pouch + immediately surrounding
  region) is encoded with **Graph Harmonic Deformation (GHD)**. A canonical mesh is
  morphed into each target mesh by gradient descent over coefficients on the truncated
  eigenvectors of the canonical cotangent graph Laplacian, producing low-dimensional
  **GHD tokens**. Extra Chamfer constraints on vessel cross-sections guide the morphing.
- **Stage-1 generator:** A **VAE over GHD tokens** (MLP-style encoder/decoder, one-shot
  decode — *not* autoregressive). Conditional generation on clinical morphological
  markers (aspect ratio AR, neck width NW, lobulation index LI, volume V) via a
  differentiable **Morphological Marker Calculator (MMC)**.
- **Morphing Energy Alignment (MEA):** KL-based constraint aligning the population
  distribution of rigidity + Laplacian-smoothness morphing energies of synthetic shapes
  with real shapes; mitigates posterior collapse under conditioning.
- **Stage 2 — parent vessels:** Centerlines encoded as warped beams with **Fourier
  tokens** (sine mode shapes); a second VAE generates centerlines conditioned on the
  aneurysm-complex GHD tokens. Cross-sections are propagated along centerlines and merged
  with the masked aneurysm complex. A tangent-matching regularizer enforces a smooth
  connection.
- **Fitting domain:** full **aneurysm–vessel segments**, including parent artery and
  **multiple openings**.

## 2. SynVA (the new toolkit) — detailed

SynVA is a **modular toolkit** that decouples healthy-vessel generation from aneurysm
synthesis, linking them through an explicit **ostium** (the ring where the aneurysm meets
the parent vessel). Pipeline: generate/obtain a healthy vessel → select an ostium →
generate an aneurysm sac conditioned on that ostium → stitch the sac back onto the vessel
→ output a single labeled mesh (vessel / aneurysm / ostium).

### 2.1 Components overview

| Code | Role | Backbone |
|------|------|----------|
| **SynVA-V1** | Healthy vessel generation | Flow-matching over a rooted spline-tree (topology transformer + geometry GNN "TreeFlowNet") |
| **SynVA-A1** | Aneurysm generation (learning-based) | Conditional **GHD-VAE**, extends AneuG — MLP decoder, one-shot |
| **SynVA-A2** | Aneurysm generation (learning-based) | **Autoregressive transformer** (OPT-350M), extends MeshAnything V2 |
| **SynVA-P1** | Procedural vessel + aneurysm generation | Rule-based, no learning |

### 2.2 Ostium selection (shared, upstream of all aneurysm generators)

The ostium is **predefined — not generated by the learned aneurysm model**. Two routes:
- **Manual (GUI):** user picks a surface vertex → local normal estimated → editable
  circular contour with user radius → vessel surface clipped to form the opening.
- **Automatic rule-based:** either **bifurcation-based** (junction from centerline
  topology; ostium = minimally curved vertex aligned with parent-vessel flow direction)
  or **curvature-based** (high-curvature centerline region; ostium at max — or sometimes
  min — surface curvature). Geometric heuristics, not a learned predictor.

The ostium supplies the attachment boundary, local scale, and growth direction.

### 2.3 SynVA-A1 (AneuG-based aneurysm generator) — the one closest to the energy work

Adapts AneuG's GHD formulation from full aneurysm–vessel segments to a **localized
"aneurysm sac + single ostium"** fitting target. It does **not** fit the parent vessel.

- **GHD fitting:** deform a canonical **sac** mesh in a shared graph-harmonic basis
  (**K = 144 modes**, 3 channels) + a global similarity transform. Target = GHD
  coefficients + fitted scale, in a common canonical eigenspace. Canonical sac built by
  ray-casting the median intersection distance across ostium-aligned training sacs.
- **Losses inherited from AneuG:** surface Chamfer + normal matching, Laplacian
  smoothing, edge-length, normal-consistency, local rigidity.
- **Key change — ostium treatment:** AneuG's full-vessel losses (differentiable
  occupancy, centerline) are **disabled**. Replaced by a **single-ostium objective**:
  opening position matched to target, opening normal aligned via robust ring estimate,
  area term prevents neck collapse, plus overlap / boundary-smoothness / relative-volume
  terms.
- **Generator:** conditional **GHD-VAE** (hidden 256, latent 108). Encoder sees the
  normalized fitted GHD target; decoder (linear + 1 residual **MLP** block) predicts GHD
  coefficients + scale. **One-shot**, not autoregressive.
- **Conditioning** (richer than AneuG): local vessel point patch (256 pts, PointNet-style
  + maxpool), ordered ostium ring (20 pts), compact ostium params (center, normal,
  radius, eccentricity), fused to a 96-D vessel-ostium feature; plus a morphology
  descriptor vector (A_A, V_A, A_CH, V_CH, D_max, H_max, W_max, H_ortho, W_ortho),
  projected to a 64-D condition embedding.
- **Three training loss groups:**
  1. **Posterior reconstruction** of the GHD target (coeff space, scale, and post-decode
     vertex space) + KL (warm-up 1000 epochs, free bits 0.02).
  2. **Geometry-aware ostium supervision** — decode to mesh, align to target ostium ring,
     then four interface losses:
     `L_geo = 5·L_attach + 10·L_center(sac) + 2·L_side + 10·L_open`
     (attachment covers prescribed ostium area; opening-center matches ring center;
     sac-center stabilizes placement; side penalizes growth through the wrong side of the
     ostium plane).
  3. **Prior-path calibration** — explicitly decode z ~ N(0,I) during training and match
     case- and batch-level statistics of the fitted targets (because inference uses the
     prior path, not the encoder).
- **Inference / stitching:** sample z ~ N(0,I), decode under the vessel+ostium+morphology
  condition, transform back to vessel frame, merge at the ostium. The opening matches the
  prescribed ostium *approximately* (soft losses), then is merged.
- **Training config:** 530 train / 132 val / 100 test; CVAE 4000 epochs, batch 96, AdamW
  lr 1e-4. GHD fits optimized per case (AdamW lr 2.5e-3, 4000 epochs).

### 2.4 SynVA-A2 (MeshAnything-V2-based aneurysm generator) — architecturally different

Generates the **triangle mesh directly** as a **discrete token sequence**, autoregressively.

- **Representation:** mesh tokenized with **Adjacent Mesh Tokenization (AMT)**; vertex
  coords discretized at **resolution 256** (vs 128 in original MeshAnything V2 — low res
  caused staircasing). Trained from scratch (pretrained weights incompatible).
- **Sequence:** `[ostium prefix tokens] → [aneurysm continuation tokens]` + BOS/EOS/PAD.
  The **ostium mesh** = all vessel faces containing ≥1 ostium vertex (a small patch, not
  just the ring curve).
- **Vessel conditioning:** local vessel submesh cropped around the ostium ([-1,1] box) →
  20,000-point cloud → frozen **ShapeVAE encoder** → 257 tokens (1 global + 256 local),
  projected to the transformer hidden size 1024. Tensor shape B×257×1024.
- **Backbone:** decoder-only **OPT-350M** transformer, trained from scratch.
- **Training:** conditioning embeddings given as input embeddings; full
  prefix+continuation sequence teacher-forced; **loss masked on the prefix**, so only the
  aneurysm continuation is learned (masked next-token cross-entropy). The condition is
  simply prepended — standard autoregressive conditioning.
- **Inference:** process vessel embeddings first ("prime the cache" = KV-cache the
  conditioning context), insert BOS, **force-feed the known ostium prefix tokens**, then
  autoregressively generate the aneurysm (EOS suppressed for a few steps; argmax
  decoding).
- **No differentiable interface loss on the opening.** Instead, exact connectivity is
  enforced at **stitch time**: ostium vertices on sac and vessel matched by **KD-tree +
  Hungarian assignment**, **snapped** to exact alignment, merged (label-consistent),
  transition smoothed.
- **Coordinate normalization:** ostium centroid → origin; ostium normal → +z; isotropic
  scale so max ostium diameter N_max = 0.25; translate −0.3 along z (generation restricted
  to +z half-space).

### 2.5 SynVA-P1 (procedural, no learning)

Rule-based generator using physiological priors. Bifurcating centerline (parent diameter
sampled; child diameters via **Murray's law**) → SDF → Marching Cubes → OpenSimplex-noise
perturbation. Aneurysm = icosphere (4 subdivisions) scaled to vessel radius, elongated
along ostium normal, noise-perturbed; optional **bleb** (p=0.3). Boolean-union merge,
remesh, Taubin smoothing, ray-cast relabeling. Used to generate the released **50,000**
labeled synthetic meshes.

### 2.6 Data & evaluation (SynVA)

- **Real data:** 769 samples from AneuX, IntrA, CMHA; unified preprocessing to
  vessel/aneurysm/ostium-labeled meshes. 100-sample stratified real test set.
- **Metrics:** mean absolute error of independent morphological parameters, paired
  Chamfer distance, distribution metrics (MMD, coverage, 1-NNA, Fréchet), + a
  2-neuroradiologist realism rating study (0–5).
- **A1 vs A2 result:** A1 is quantitatively better (lower param deviation + Chamfer) but
  slightly more symmetric; A2 rated marginally more realistic by experts despite weaker
  metrics and ~66% generation success. Presented as complementary.

## 3. One-line disambiguation for the coding agent

- **AneuG = the energy work** (GHD tokens + MEA + MMC, two-stage VAE, joint aneurysm
  complex + parent vessel, MLP/one-shot decode, multi-opening full-segment fitting).
- **SynVA-A1 = AneuG adapted** to ostium-conditioned, sac-only GHD-VAE generation on an
  existing vessel (still MLP/one-shot; adds vessel-ostium + morphology conditioning,
  interface losses, prior-path calibration).
- **SynVA-A2 = a different model** — autoregressive transformer (OPT-350M, MeshAnything
  V2 + AMT) that generates the mesh token-by-token from an ostium prefix; connectivity via
  KD-tree/Hungarian snapping, not a differentiable loss.
- **SynVA-V1 = healthy vessel generator** (flow matching over spline-tree).
- **SynVA-P1 = procedural generator** (rules + Murray's law), source of the 50k dataset.
